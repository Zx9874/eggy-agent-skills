## 当前地图动工顺序

1. 先读本地图受管区块之外的项目专属说明，以及根 `README.md`（项目总览）的当前玩法、架构和状态。
2. 定位唯一需求文档、开发计划、资产清单、项目 README 和开发日志；不要为单个功能再建一套长期文档。
3. 修改前记录当前 Git 提交、已有未提交改动、允许修改的文件和禁止修改的文件。
4. 涉及玩家时先写清数据是全图一份还是每玩家一份、结果发给谁；多人地图不能用单一全局值覆盖玩家上下文。
5. 涉及接口时先按公共规则完成查证，证据写入开发计划后才能编码；涉及结构变化先扫描导出契约。

## 项目文件边界

{{EDITION_RULES}}

- 自定义功能代码放项目自建模块目录；`main.lua`（主入口）只做必要装配，重要文件必须被入口引用。
- `Data/`、`data/`、接口定义、官方配置、`.codemaker/`、`.vscode/` 和官方生成内容只读。
- 地图 Lua 文件名使用英文、数字和短横线或下划线，不使用中文文件名。
- 资产编号、预设和 UI 节点按真实用途记录在唯一资产清单；测试资产显式标记 `【测试专用】`。

## 测试与交付门槛

- 没有用户要求不得启动编辑器或试玩。
- 测试只为解决当前卡点，先小范围修改并加入中文 `【测试专用】` 诊断日志；证据足够后退出测试模式并清理测试代码。
- 修复前先解释报错原因；修复后说明保留了什么效果、改动了什么和原因，解释使用大白话。
- 用户没有确认试玩结果时，开发计划只能写“待试玩”或“待用户确认”。
- 交付前审查接口调用、逻辑、并发/状态归属、性能、日志等级、注释、导出契约、文件名和 Git 差异。
