# {{PROJECT_NAME}} 开发日志

> 本文件记录已经发生的开发批次，不代替开发计划。每个批次引用计划编号，不重复抄写整段用户原话。

## 批次记录模板

### 日期与计划编号：待填写

- 修改目的：待填写；原因只能引用用户明确说明或已验证限制
- 动工前提交：待填写
- 涉及文件：待填写
- 修改前表现：待填写
- 修改后表现：待填写
- 保持不变的功能：待填写
- 新增或变更资产：待填写；没有则写“无”
- 接口查证结果：待填写
- 导出契约变化：没有；如有必须写用户确认和可视化侧交接
- 静态检查：待填写
- 试玩结果：待试玩、失败、部分通过或用户确认通过
- 本地提交：待填写
- 恢复依据：通常填写动工前 Git 提交号和已有差异；只有 Git 无法覆盖的场景/UI/预设状态才填写本批快照路径
- 新知识沉淀：待填写；没有则写“无新发现”

## 写作边界

- 只记录客观改动、用户明确原因和验证结果。
- 不在代码注释里堆叠多代开发历史。
- 没有真实试玩时不能写“功能正常”。
- 一次完整开发批次更新一次，不随每次保存反复写日志。
