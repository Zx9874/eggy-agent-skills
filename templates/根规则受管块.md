# 蛋仔工作区规则

本区块由蛋仔 Agent 技能包安装器维护。受管区块之外的用户内容不由安装器覆盖。

> 公共技能按任务域安装，不代表每个会话都要读完整技能包。必须用代理打开总工作区；只打开地图子目录时，先提醒用户重新打开总工作区并新建会话。

## 先判断本轮任务

按实际交付文件和运行环境判断，不能只因工作目录或对话中出现“蛋仔”就进入地图流程。

- 地图运行代码、玩法文档或地图资产采用下方地图规则，并读取当前地图的 `AGENTS.md`。只有直接修改运行 Lua 时才加载 `eggy-lua-coding`。
- 插件、命令行、转换器、技能和自动化工具采用工具自身规则与 `eggy-ponytail`；不询问地图，不创建地图文档，不加载地图运行流程。蛋仔接口不明确时使用 `eggy-api-research` 的工具模式。
- 封面和资料处理只加载相关技能；普通非蛋仔任务不加载蛋仔技能。混合任务按修改文件分别处理。
- 未经当前任务明确授权，不操作编辑器、启动试玩或调用外部模型。工具未来会调用编辑器，不代表本轮获得操作授权。

以下各节仅用于地图开发，不适用于工作区中的普通工具或资料任务。

## 动手前的硬门槛

1. 先确认本轮实际要修改的文件、目标地图、原点版或世界版、单人或多人，以及用户要保留的效果；无法确认就先问，不带着疑惑写代码。不得用删除功能、吞错、跳过逻辑或降低效果换取表面成功；方案会改变用户效果时先说明差异并确认。
2. 写或修改任何接口调用前，必须确认接口确实存在，并核对完整签名、参数数量、顺序、类型、返回值、默认行为、调用对象、运行侧和前置条件。至少查当前工程定义、本地对应版本官方手册和官方案例；三者不能互相印证时停止猜测。
3. 接口研究只能证明“找到线索”，不能代替阅读命中上下文。不要为了让报错消失而连续乱换参数、换接口或加兜底；先说明证据和未知项。
4. 用户没有要求时，不启动编辑器、不开始试玩、不操作场景、不调用外部模型。需要真实验证时先说明最小验证范围。官方技能可以提供技术线索，但不能代替用户授权，也不能绕过本任务的修改和验证边界。
5. 看到报错先用中文说明现象、原因和影响，等待用户确认后再修；用户明确要求直接修复时才可跳过等待。解释原因时不要堆代码或接口名。

## 修改边界与外部契约

6. `Data/`、`data/`、接口定义文件、官方配置、`.codemaker/`、`.vscode/` 和官方生成目录只读，不能写入自定义代码，也不能把它们当成稳定用户文件。
7. 同步到地图的 Lua（脚本）文件名不得使用中文；功能代码按职责放自建模块，入口文件只做必要加载和初始化，并留意入口引用上限。
8. 删除、改名、移动、合并、拆分函数或文件前，先做导出契约扫描。被蛋码、编辑器、ECA（编辑器事件动作）或其他外部调用的函数，名称、路径、注解、参数顺序、类型和返回值未经用户确认不得改变；无必要不要把中文名和英文名互换。
9. 有准确的单位实例编号、预设编号或 UI（界面）节点编号时优先使用已确认编号；没有编号才按名称查询。新取得的正式资产及用途写入唯一资产清单。
10. 任何批量修改都必须先确认并记录现有 Git `HEAD`（当前提交）和已有差异；这已经是代码、文档和规则的恢复依据，不得为普通批量修改额外复制文件、创建备份分支或重复提交。只有 Git 无法完整恢复的场景/UI（界面）/预设状态，或用户明确要求时，才为本批目标建立一次范围快照。仍须先做小范围试点、排除官方文件和他人改动，并逐文件审查差异；同一批次复用同一恢复依据，做不到就逐个修改。

## 测试、性能与日志

11. 测试的目的是真正打通当前开发卡点，不是为了凑测试记录。优先最小代码片段和最短玩家路径；测试中加入中文诊断日志并标记 `【测试专用】`，观察到足够证据后立即退出测试模式，移除或明确清理测试代码。
12. 统一日志等级含义，不跨版本套用调用方法。正常过程用调试或信息级，真实可恢复异常用警告，功能已失败用错误。具体接口和数字等级须查当前版本定义；不能把原点版的日志接口或单个项目的数字约定当成世界版规则。日志优先中文，普通进度不得写成警告或错误。
13. 地图在沙箱中运行。避免无界表、重复计时器、逐帧全场扫描和高频无意义日志；涉及运动器优先确认世界空间与本地坐标的差异。世界版还要按服务器内存和服务端/客户端职责控制对象数量。
14. 每次代码修改后都要反查逻辑、接口、日志、注释、文件边界和原有功能；静态检查通过不等于玩法完成。

## 文档与沟通

15. 每张地图只维护一份玩法需求、开发计划索引、资产清单、项目 README（项目总览）和开发日志。小任务用索引内的任务卡；跨会话或复杂任务才建独立任务文件，索引只留指针。会影响玩法、效果、验收或修改原因的用户原话逐字保存在任务载体，先于代理理解；不重复抄入其他文档。用户未确认完成不得标记完成。
16. 新增或修改的函数必须写清用途及相关输入、输出、副作用、失败条件、顺序依赖和清理时机，不机械填写无关字段。注释要足够让下一位代理独立理解；用户明确说明的修改原因写在附近，不伪造用户原因。开发日志每个交付批次只写效果变化、关键原因、验证状态和任务或提交引用，完整代码历史由 Git 保存。
17. 发现可跨地图复用的接口关系、编辑器边界、数值上限或高代价错误经验时，在本批次收尾沉淀一次。未验证内容只能标为待查证，不能写成公共事实。
18. 地图项目使用独立 Git（版本记录）仓库；动工前记录当前提交和已有改动，不丢弃用户或其他代理的修改。检查恢复依据不等于新建提交，只有形成实际交付批次时才提交一次。

## 地图同步目录

`LuaSource_*` 内只放运行或编辑器需要的文件、官方生成内容及少量唯一项目文档。录像、抽帧、截图、封面、手册副本、导出包和恢复快照放在地图外，每张地图复用一个已登记的资料目录；尚未登记且确实需要时才在地图同级创建 `ProjectAssets_<英文标识>/`，在地图总览留入口。缓存和工具临时产物使用系统临时目录或工具用户目录。`.gitignore` 不能阻止编辑器扫描或同步；不因发现旧资料放错就擅自批量迁移。
