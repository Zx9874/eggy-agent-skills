# Lua 与蛋码自定义事件

## 先画两端协议

编码前在开发计划记录：

| 项目 | 必填内容 |
|---|---|
| 发送方 | Lua 或蛋码 |
| 接收方 | Lua 或蛋码 |
| 事件名称 | 当前可视化配置中的准确名称 |
| 参数 | 顺序、类型、含义和允许空值 |
| 变量关系 | Lua 参数对应哪个蛋码变量 |
| 触发时机 | 谁先执行、是否可能重复或自触发 |
| 失败表现 | 丢事件、空值、类型不符或旧绑定 |

事件名称、导出函数名称和蛋码变量关系来自用户当前可视化配置，不能由代理自行翻译、改名或补齐。

## 接口查证

分别查证发送、监听、回发或导出函数涉及的每个接口：当前工程完整签名、官方手册语义、官方示例组合和运行位置。旧技能示例、其他地图和模型记忆只可帮助搜索。

资料只能证明事件支持某种数据形式时，不得外推到其他类型。默认值、空值、数组、对象和多返回值没有证据就标未知并询问用户或做最小测试。

## 组合模式

- 只通知：事件本身携带已经确认的参数。
- 请求后取值：事件负责通知，导出函数负责让蛋码按已绑定名称取值。
- 双向回发：两边各有明确事件，必须防止同名事件或转发逻辑自触发循环。

选择模式前先确认用户真实效果，不因为某个模式写起来方便而改变交互。

## 验收

检查事件名称、发送与接收方向、参数顺序与类型、每个玩家的接收范围、重复触发、空值和导出契约。需要蛋码重新绑定的步骤逐项告诉用户，并保持“待用户确认”。
