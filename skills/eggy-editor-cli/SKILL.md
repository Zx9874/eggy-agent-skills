# 蛋仔编辑器命令行

## 工具与连接

工具位于当前 Windows 用户目录：

```powershell
$CLI = Join-Path ([Environment]::GetFolderPath('UserProfile')) '.eggitor\cli\editor-cli.exe'
```

- 禁止调用工程 `.codemaker\editor-cli.exe`，该路径已经废弃。
- 禁止写死端口；连接失败时检查编辑器是否启动和同目录动态配置。
- 工具不存在时提示用户启动或更新编辑器，不手动伪造目录和配置。
- 命令或参数不清楚时读取本机 `--help`；已经在当前工具版本稳定使用的命令不需要每轮重新研究。

## 执行

1. 确认目标工程、原点版或世界版，以及编辑器当前打开的地图。
2. 用 `status` 确认连接和编辑或试玩状态。
3. 需要观察日志时先记住 `log.txt` 当前字节位置，执行后只读新增部分。
4. 一条命令只做一个明确目的，优先使用能证明或推翻当前判断的最小命令。
5. 检查退出状态、编辑器状态、返回值、增量日志和必要截图；命令成功不等于游戏效果成功。

`status`、日志读取和截图等工具命令按本机帮助执行，不需要为它们建立任务接口证据卡。通过 `exec` 或 `eval` 调用编辑器或运行时接口时，接口本身仍须按编码技能查当前工程定义和官方资料。

## 编辑器进程清理红线

进程终止不可恢复，且可能造成未保存地图丢失。严格执行以下边界：

1. **只清理用户明确指定的目标。** 用户可以用进程编号、唯一地图名或“全部编辑器”等无歧义范围授权；“清理残留进程”“把没用的杀掉”等笼统说法只授权检查和列候选，不授权代理自行判定并终止。
2. **当前世界编辑器中，窗口标题 `EGGITOR` 是草稿启动界面。** 禁止把它称作空壳或仅凭标题终止。高内存、无地图名、父进程、子运行端已退出、窗口异常或“看起来没用”都只是诊断证据，不是用户授权，也不能证明进程属于残留。
3. 动手前逐项列出候选进程的编号、可执行文件路径、窗口标题、父子关系、对应地图、编辑/试玩状态和可能存在的未保存内容，并分为“用户指定目标”“明确保护”“身份不明”。任一项无法唯一对应时，说明问题和影响，等待用户选择。
4. 父进程、子进程和网页辅助进程分别视为独立目标。用户只点名一个进程时，不自动扩大到其父级、子级、同名进程或整棵进程树；目标是其他活动编辑器的祖先或依赖时，必须先告诉用户风险并等待决定。
5. 终止前重新读取目标身份。只使用精确进程编号操作，禁止按 `client.exe` 等进程名批量结束；身份、编号或父子关系发生变化时立即停止。
6. 用户只要求诊断、查询或解释时保持只读。用户明确确认终止后，仍不得保存、关闭或处理范围外地图来“顺便收尾”。
7. 终止后验证指定目标是否退出、所有保护进程是否仍存活且连接到原地图，并报告实际终止项、保留项、内存变化和不可恢复性。验证失败时只报告，不继续扩大清理。

典型边界：若崩溃地图的进程已经不存在，而高内存的 `EGGITOR` 草稿启动界面仍在，只报告两项事实；未经用户明确点名草稿启动界面，不得把清理范围从已消失的崩溃进程扩大到启动界面。

## 最小检查与研究

- 已查证、只读、单一目的的内联查询可以直接执行。
- 可恢复且只影响一个测试对象或一个参数的检查，可以在明确范围后执行并读回结果。
- 涉及持久场景修改、跨帧状态、事件监听、多步骤生命周期或可能阻断正式流程时，改用项目代码或现有测试位置。
- 只有现有位置无法安全隔离时才创建独立测试文件；创建的测试代码与日志必须带 `【测试专用】`。
- 接口首次报错、无效果或作用对象错误时转入 `eggy-api-research`，不要在命令行里连续拼接不同写法和多个参数碰运气。

## 修改边界

- 只读清点可以一次返回范围明确的结果；创建、删除、移动和修改场景内容先单点执行并读回，再决定是否扩大。
- 精确且稳定的实例编号可用时优先使用；没有编号时结合唯一名称、父级、层级、类型、标签或属性，并核对返回数量。
- 编辑器包装对象只使用实际公开能力，不假定等同运行期单位。
- `clear-logs` 会破坏证据，未经用户明确要求不得使用。
- 新确认的正式实例、预设或界面节点写入资产清单；普通查询过程不写任务载体。

向用户简洁说明连接的工程、执行动作、结果证据、新增资产和仍需用户完成的最短操作，不粘贴整段命令或原始日志。
