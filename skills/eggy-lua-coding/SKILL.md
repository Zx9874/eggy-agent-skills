# 蛋仔 Lua 开发

本技能只用于直接落入地图工程的运行 Lua。编辑器插件、命令行封装、转换器、技能和自动化工具使用 `eggy-ponytail`（蛋仔极简开发）及工具自身规则，不加载地图运行流程。

## 开工硬门禁

1. 确认当前地图工程、原点版或世界版、单人或多人，以及当前任务的玩家可见效果。
2. 读取工作区规则、地图规则、根 `README.md`（项目总览）和开发计划活跃任务；只加载本任务需要的资料。
3. 修改前记录地图仓库根、当前提交、已有未提交改动、允许修改文件和禁止修改文件。已有 `HEAD`（当前提交）和差异记录就是代码恢复依据；这里是记录基线，不是创建备份的指令。不得为普通代码、文档、规则或批量修改额外复制文件、创建备份分支或重复提交；只有 Git 无法覆盖的编辑器场景/UI/预设状态，或用户明确要求时，才建立一次本批目标范围快照。
4. 写代码前列出本次准备使用的每个 API。对每个 API 必须确认：是否存在、所属对象、点号或冒号调用形式、参数数量与顺序、每个参数类型和含义、返回值、默认值、范围、运行端、调用前提和失败表现。
5. API 证据至少来自当前工程定义、对应版本官方手册和对应版本官方示例；任何一处冲突或未知都不能用猜测替代。运行接口查证脚本只提供命中线索，不能代替人工阅读上下文。
6. 世界版涉及大方向、服务端状态、存档、多人生命周期或跨端通信时，先定向阅读对应官方教程和只读官方模板；模板用于校正路线，不代表其中每个写法都正确。

完整公开硬规则见 [hard-rules.md](references/hard-rules.md)。

## 版本分流

- **原点版**：按当前工程的帧同步、真实物理和沙箱边界开发；不默认存在世界版的持续统一世界或随进随出。
- **世界版**：先划分服务端权威状态、客户端表现和公共协议；不把每玩家显示状态当成全世界共享状态，也不把原点版回合重演假设套过来。
- 两版同名 API、导出注解、事件或参数关系必须分别查证。版本不明、配置冲突或运行端不明时停止。

## 文件和外部契约

- 官方生成目录、数据映射、接口定义、工程配置、`.codemaker/` 和 `.vscode/` 只读；禁止把自定义代码写入 `Data/` 或 `data/`。
- 功能代码放自建模块目录；入口文件只做必要引用和初始化。新增文件名和同步到地图的 Lua 文件基本名不使用中文。
- 删除、改名、移动、合并、拆分函数或文件，以及修改参数或返回契约前，先使用 `eggy-lua-export` 扫描。命中外部导出函数时冻结名称、路径、注解、参数顺序、类型和返回值，除非用户确认精确变化。
- 已确认的实例、预设和界面节点编号写入唯一资产清单；准确编号优先于名称查询。

## 实现和注释

- 先复用当前工程中职责正确的模块和状态所有者；只实现本次用户效果，不为未来猜需求增加抽象。
- 每个新增或修改函数必须说明用途；复杂函数还要说明输入、输出、副作用、失败条件、清理时机和顺序依赖。用户明确说过的修改原因写在附近注释并关联任务编号，代理推测不能伪装成用户原因。
- 运动器或变换逻辑按当前工程证据选择坐标系；没有明确理由时优先验证世界空间，不能凭其他版本代码套用。
- 地图是沙箱运行环境，避免无界表、重复计时器、逐帧全场扫描和无意义高频日志。世界版服务端资源尤其不能未经必要性评估就堆放全场对象。

## 兼容与故障范围

- 新建持久化功能，修改存档字段、含义、默认值、标识、读写或初始化依赖，以及核对相关发布风险时，按需读取 [存档兼容与故障隔离](references/save-compatibility.md)。旧玩家数据是发布间的契约，不能只验证新玩家空档。
- 以保留玩家和地图既有数据、恢复原有玩法为共同目标。先兼容旧结构、修正读取与映射或从可信进度恢复缺失运行状态；无法立即安全恢复时才按真实依赖临时保护，并实现解除保护后的继续初始化。单字段、单玩家或非关键服务异常不得默认中止整图；不能加完拦截就交付。
- 读取失败不等于没有存档；不得用默认值覆盖未知进度、擅自重置玩家权益或伪造成功。数据没丢但核心玩法仍锁定，属于未修复；验收须覆盖旧进度保留、玩法恢复、新进度保存及重进。

## 玩家操作反馈

新增或修改玩家交互时，成功、条件不满足和实际存在的等待路径都属于功能实现，不能只写成功路径。玩家应能判断这次操作是否生效、未生效的原因以及是否还能继续。两版共用此标准，实现接口和运行端分别查证。

- 动手前沿“操作入口 → 条件判断/实际执行 → 结果接收 → 玩家可见表现”追踪本次调用链，包括下层拒绝、提前返回、禁用按钮和异步失败；收尾按实际改动复查。每个阻止操作的分支都要能指出玩家在哪里看到结果或原因，不能以空返回、只写日志、只返回真假或错误码结束整条交互链。内部函数可以返回原因，由现有界面层统一呈现，不要求每层都弹提示。后台清理、失效回调不机械加提示。
- 主动判断本次交互是否需要音效、特效或动画来改善手感、结果辨识或奖励感，不能把“数据变了、已有文字”当作体验完整。按玩法风格、动作频率和重要程度取舍：命中、拾取等高频动作宜短促轻量，解锁、达成目标可更突出，普通切换不必庆祝。已有表现合适就复用，不要求每次操作配齐声音、特效和动画。
- 门打开、物品出现等变化已清楚说明成功就不再弹窗；按下动画只证明收到输入，不证明交易成功。不可用按钮不能只置灰，原因须在当前操作处可见或可直接查看，不能依赖已被禁用的点击回调。条件恢复后更新可用状态。
- 声画效果沿用真实结果与接收者约束：按下反馈可立即给，成交、奖励效果须在结果确认后播放；拒绝不能播放成功效果，也不能仅用音效代替原因。优先复用已查证可用且风格合适的资源与播放入口，缺素材时说明具体需求，不编资源编号或宣称已完成。高频触发避免长音、粒子重复堆积，不遮挡目标和界面；循环声音和临时特效按持续时间、取消及离场条件停止或回收。
- 拒绝时说明真实、具体的原因，例如“金币不足，还差 20”“背包已满，请先腾出空位”；准确差额必须来自可信的本次判断，未知就不编数值。价格或按钮变色不自动算解释清楚；不把所有失败归为钱不够或“操作失败”，也不为补反馈放宽购买、解锁等条件。
- 有等待就给出轻量处理中状态，并有成功、失败及无响应时的收束路径，不能永久锁住按钮。按负责该结果的权威状态给出结论；世界版不能用客户端预判冒充服务端交易结果。结果未知时说明仍待确认，沿现有查询/恢复路径处理，不能假报失败、直接重试扣款或在连点时重复执行。已清楚显示处理中时不逐次提示连点；过期结果不覆盖新界面状态。
- 个人操作反馈发给相关玩家，共享结果按玩法归属同步，不把个人拒绝向全图广播。复用现有提示入口，避免上下层各报一次。高频重复反馈合并或限频，但首次拒绝和原因变化不能被误吞；重要结果不能只靠声音、颜色或瞬时文字。钱不够、未解锁等正常拒绝不升级成警告或错误日志。技术诊断只进运行日志，不当玩家文案；真实故障仍要定位修复，不能用提示遮掩。
- 本次交互的必要反馈直接补足，不为每句提示追问；改变玩法、泄露刻意隐藏的信息、新增交互流程或资产时再确认。不顺手全图加提示，不新建反馈框架、分支台账或测试文件。随本次验证检查成功、相关拒绝及拒绝后恢复；具体范围见测试技能，不因本节另开测试流程。

## 测试、报错和收尾

- 没有用户要求不得启动编辑器或试玩。静态检查不能冒充玩法完成。
- 测试是为打通当前卡点服务：先读差异和已有日志，再做最小可回退试点；优先复用 Git 差异和现有测试位置，不为每次实验复制备份。需要行为证据时只加入能判断入口、关键条件和结果的 `【测试专用】` 诊断，不把测试模式带入正式代码。
- 看到报错先用中文解释最早根因和影响，按用户授权决定是否修复；接口无效果或候选不明时转接口研究，不连续换参数碰运气。
- 收尾逐文件审查逻辑、API、状态归属、清理路径、注释、日志、玩家操作反馈和导出契约；更新必要的任务、资产、总览和知识记录。用户未确认前状态只能是待试玩或待用户确认。
