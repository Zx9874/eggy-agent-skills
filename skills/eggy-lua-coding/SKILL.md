# 蛋仔 Lua 开发流程

## 开工前

1. 确认代理打开的是总工作区，再确认地图工程、原点版或世界版以及单人或多人。只打开地图子目录时先提醒用户重开总工作区和新会话。
2. 读取工作区和地图工程的代理规则，再读取唯一需求、开发计划、资产清单、项目说明和开发日志。
3. 运行版本状态检查，记录仓库根目录、当前提交和已有未提交改动。仓库根必须等于地图工程根。
4. 把用户原话、代理理解、可试玩验收标准、允许修改文件和禁止修改文件写入开发计划。
5. 回答多人检查：数据全图一份还是每玩家一份，显示或结果发给谁。

## 接口门禁

列出方案涉及的每个接口。对每项执行：

1. 在当前工程接口定义中找到完整名称和签名。
2. 在当前版本本地官方手册中确认语义、单位、范围、默认值、调用前提和失败表现。
3. 在对应版本的官方示例或案例中搜索典型用法；该版本没有案例或没有命中也要如实记录。
4. 使用 `<总工作区根>\.eggy-agent\scripts\api-preflight.ps1` 获取真实搜索命中，再人工阅读上下文。
5. 在开发计划写清文件、行号、参数、返回值、未知项和结论。

任一接口不存在、参数关系未知或资料冲突时立即停止。模型记忆、旧代码、其他地图和旧知识库都不能代替查证。

## 结构与导出保护

- 官方生成文件和数据映射目录只读；功能代码放自建模块目录。
- 入口文件只做必要加载和初始化，不堆功能逻辑。
- 原点版使用根入口和自建模块；世界版先划分服务端权威状态、客户端本地表现和公共协议，分别放入对应目录，禁止跨侧混用状态。
- 接口的点号或冒号写法必须逐项服从当前工程声明，不得把任一版本概括成全部同一种写法。
- 删除、改名、移动、合并、拆分或修改函数签名前，加载 `eggy-lua-export` 并执行导出契约扫描。
- 命中导出函数后，不得通过删注解、改局部函数、加空壳或别名绕过；先取得用户对精确变化的确认。
- 多文件修改逐文件进行。需要机械批量操作时，先建恢复点、试点一个文件、精确匹配，再逐文件审查差异。

## 编码要求

- 保持用户功能、外观和时序；方案会改变效果时先确认。
- 新增或修改文件补齐文件职责、入口、依赖、状态所有权和关键约束。
- 每个函数说明用途；复杂函数说明输入、输出、副作用、失败条件、清理时机和顺序依赖。
- 用户明确说明的修改原因写入注释并关联计划编号；代理推测只写待确认区。
- 测试代码和日志使用“【测试专用】”。
- 避免无界表、重复计时器、逐帧全量扫描、高频重复查询和无意义日志。

## 收尾

1. 反向列出实际调用的全部接口，与查证记录逐项核对。
2. 加载日志技能审查等级、频率、测试标记和本次增量日志。
3. 再次扫描受影响文件的导出契约，并检查版本差异中没有未确认变化。
4. 审查逻辑、多人状态、清理路径、失败路径和注释一致性。
5. 更新开发日志、资产清单和知识沉淀；没有新知识写“无新发现”。
6. 静态检查通过只能写“待试玩”。用户亲自确认后才能写“已完成”。
