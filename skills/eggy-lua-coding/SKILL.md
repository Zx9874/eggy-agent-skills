# 蛋仔 Lua 开发

本技能只用于直接落入地图工程的运行 Lua。编辑器插件、命令行封装、转换器、技能和自动化工具使用 `eggy-ponytail`（蛋仔极简开发）及工具自身规则，不加载地图运行流程。

## 开工硬门禁

1. 确认当前地图工程、原点版或世界版、单人或多人，以及当前任务的玩家可见效果。
2. 读取工作区规则、地图规则、根 `README.md`（项目总览）和开发计划活跃任务；只加载本任务需要的资料。
3. 修改前记录地图仓库根、当前提交、已有未提交改动、允许修改文件和禁止修改文件。已有 `HEAD`（当前提交）和差异记录就是代码恢复依据，不得为普通代码、文档、规则或批量修改额外复制文件、创建备份分支或重复提交；只有 Git 无法覆盖的编辑器场景/UI/预设状态，或用户明确要求时，才建立一次本批目标范围快照。
4. 写代码前列出本次准备使用的每个 API。对每个 API 必须确认：是否存在、所属对象、点号或冒号调用形式、参数数量与顺序、每个参数类型和含义、返回值、默认值、范围、运行端、调用前提和失败表现。
5. API 证据至少来自当前工程定义、对应版本官方手册和对应版本官方示例；任何一处冲突或未知都不能用猜测替代。运行接口查证脚本只提供命中线索，不能代替人工阅读上下文。
6. 世界版涉及大方向、服务端状态、存档、多人生命周期或跨端通信时，先定向阅读对应官方教程和只读官方模板；模板用于校正路线，不代表其中每个写法都正确。

完整公开硬规则见 [hard-rules.md](references/hard-rules.md)。

## 版本分流

- **原点版**：按当前工程的帧同步、真实物理和沙箱边界开发；不默认存在世界版的持续统一世界或随进随出。
- **世界版**：先划分服务端权威状态、客户端表现和公共协议；不把每玩家显示状态当成全世界共享状态，也不把原点版回合重演假设套过来。
- 两版同名 API、导出注解、事件或参数关系必须分别查证。版本不明、配置冲突或运行端不明时停止。

## 文件和外部契约

- 官方生成目录、数据映射、接口定义、工程配置、`.codemaker/` 和 `.vscode/` 只读；禁止把自定义代码写入 `Data/` 或 `data/`。
- 功能代码放自建模块目录；入口文件只做必要引用和初始化。新增文件名和同步到地图的 Lua 文件基本名不使用中文。
- 删除、改名、移动、合并、拆分函数或文件，以及修改参数或返回契约前，先使用 `eggy-lua-export` 扫描。命中外部导出函数时冻结名称、路径、注解、参数顺序、类型和返回值，除非用户确认精确变化。
- 已确认的实例、预设和界面节点编号写入唯一资产清单；准确编号优先于名称查询。

## 实现和注释

- 先复用当前工程中职责正确的模块和状态所有者；只实现本次用户效果，不为未来猜需求增加抽象。
- 每个新增或修改函数必须说明用途；复杂函数还要说明输入、输出、副作用、失败条件、清理时机和顺序依赖。用户明确说过的修改原因写在附近注释并关联任务编号，代理推测不能伪装成用户原因。
- 运动器或变换逻辑按当前工程证据选择坐标系；没有明确理由时优先验证世界空间，不能凭其他版本代码套用。
- 地图是沙箱运行环境，避免无界表、重复计时器、逐帧全场扫描和无意义高频日志。世界版服务端资源尤其不能未经必要性评估就堆放全场对象。

## 测试、报错和收尾

- 没有用户要求不得启动编辑器或试玩。静态检查不能冒充玩法完成。
- 测试是为打通当前卡点服务：先读差异和已有日志，再做最小可回退试点；优先复用 Git 差异和现有测试位置，不为每次实验复制备份。需要行为证据时只加入能判断入口、关键条件和结果的 `【测试专用】` 诊断，不把测试模式带入正式代码。
- 看到报错先用中文解释最早根因和影响，按用户授权决定是否修复；接口无效果或候选不明时转接口研究，不连续换参数碰运气。
- 收尾逐文件审查逻辑、API、状态归属、清理路径、注释、日志和导出契约；更新必要的任务、资产、总览和知识记录。用户未确认前状态只能是待试玩或待用户确认。
