# 存档兼容与故障隔离

新建持久化功能，修改存档字段、含义、默认值、编号、序列化、读写或初始化依赖，以及检查相关发布兼容性时读取。本文件规定工程处理原则，不替代当前版本接口查证，也不要求建立通用迁移框架。

目标是保留玩家和地图既有数据，并恢复原有玩法及后续进度保存。数据保全是恢复的约束，不是交付终点；保留旧数据却持续锁住核心玩法，仍属于未修复。

## 先认清数据契约

- 沿“读取 → 识别旧结构 → 转换与校验 → 功能初始化 → 保存”追当前调用链，包括自动保存、退出和关闭路径；不能只改读档函数。确认存储标识、字段含义、版本识别依据和兼容逻辑的唯一负责模块。
- 对照已发布代码或已有脱敏样例，找出仍可能留在玩家端的旧结构，包括跨过多个更新的玩家。没有版本字段不等于坏档；按有证据的旧结构识别，不能凭空编造历史格式。缺少历史证据时明确兼容性未验证，不阻塞无关开发，也不能宣称可以安全发布。
- 不为新功能改存储标识以绕过旧档，也不擅自清空、丢弃未知字段、退役物品或领取记录。合法的 0、false、空串与字段缺失要按实际含义区分；新增字段默认值不应覆盖已有值。
- 两版共用数据保护原则，接口与运行方式分别查证。原点版遵守帧同步和官方存档机制，不能自行套入世界版异步流程；世界版先区分 ArchiveService（存档与成就服务）和 DataStoreService（数据存储服务），不混用保存、失败或并发保证。

## 按证据处理，不按“异常就重置”

| 实际情况 | 处理边界 |
| --- | --- |
| 成功读取，且按当前接口语义确认没有历史数据 | 使用已确认的新玩家初值，再允许对应初始化和保存；返回默认值或版本号缺失本身不证明是新玩家。 |
| 可识别旧结构、缺少新增字段 | 做最小的无损转换或补全，再校验受影响数据；已有进度保留。 |
| 局部字段无效 | 只有含义已确认、可从可信数据重建且不影响权益时，才局部修复。金币、付费物品、背包、解锁和奖励领取等不可擅自归零或重发。 |
| 读取失败、超时或仍未完成 | 数据未知，不是新档。可用临时显示，但禁止把它作为正式资产、发奖依据或写回默认值。 |
| 未识别结构、比代码更新的存档版本 | 保留数据，临时保护受影响写回与操作；继续查对应发布结构，补兼容读取或已证实可行的迁移路径，不能只加拒绝加载就交付，也不能降级覆盖。 |

“只修一处”不等于“其他数据必定安全”。若多个字段共用一整份序列化存档，局部恢复后也必须保留其他有效与未识别进度；无法安全保留时，禁止整份写回。确需有损重置、删除旧进度或缩小兼容范围时，先说明具体损失并取得用户确认，不把它包装成技术修复。

## 初始化与写回分别判断

- 优先修复读取、转换或配置映射，让有效旧数据继续驱动玩法；不要把代码不能识别的数据直接判为玩家坏档。场景、界面或运行对象未恢复时，依据可信进度重建缺失状态，不通过清空存档迫使整图从头初始化。

- 地图公共启动、玩家数据加载和具体功能就绪按真实依赖处理。检查顶层返回、抛错、永不结束的等待和“所有玩家都成功才就绪”条件；单玩家或非关键功能失败不应使无关流程停止。
- 暂停范围取能保护数据的最小依赖集合。钱包不可信时暂停该玩家的购买及相关结算，不能只禁用商店界面却放任其他扣款路径。共享关键状态损坏可能影响所有依赖方，应明确范围；不能靠伪造成功强行开局。
- 未完成可靠加载或未完成兼容校验的数据，在定时、退出、关闭等任何路径都不能被默认值覆盖。使用项目已有状态或最小标记统一决定能否写回，不为每个调用方各造一套规则。
- 设计并验证解除保护的条件和恢复入口，不能只实现锁定分支。数据重新可用或转换成功后，在当前运行机制允许时接续受影响阶段、解除临时锁定；必须重进才能恢复时说明实际原因，不默认让玩家反复重进。异步回调须属于当前玩家会话，不得重复创建单位、绑定事件、扣款或发奖。
- 向玩家说明实际不可用的功能和可执行下一步，不暴露内部字段或堆栈，也不让界面无限加载。诊断日志记录阶段、版本判定、影响范围和恢复结果，合并重复错误，不打印整份存档或每帧刷屏。

隔离只是临时保护。代理在授权范围内应继续完成兼容、局部恢复和验证，不能加完拦截就收尾。只有缺少可信数据、外部服务持续不可用或需要有损处置授权等确实无法继续的情况，才说明阻塞、已采取的恢复措施及最小所需条件；不得猜造余额、进度或奖励来冒充正常游玩。

## 转换与保存

- 在现有存档模块集中做转换，先生成并校验候选结果，成功后才采用对应结构版本；同一旧输入重复转换、重进或重试不能多发奖励、重复扣款或改变已迁移结果。
- 转换函数只处理数据，不混入发奖、建物体等外部副作用。需要基于旧值更新时，先查当前接口的冲突与重试语义，不能假设多字段或多次写入是事务。
- 保存失败不报告已落盘，不丢弃仍需保存的有效结果；重试要有限频、次数或超时边界，不能无界堆积。内存中的待保存状态不能保证服务器关闭后仍可恢复，尚无可靠恢复路径的风险必须说明。
- 回滚代码不等于回滚玩家存档。新版已写入的数据，旧代码能否识别必须另查；不把 Git（代码版本记录）或换存储标识当作存档回滚方案。

## 最小兼容验收

只在上述契约或初始化链变化、首发持久化功能或相关发布核对时执行；同一数据驱动批次合并关联场景，不为每个字段开一轮试玩。复用现有纯逻辑检查和已发布结构的脱敏样例，不能只用按新格式造出的“旧档”证明兼容，也不读取或改写线上玩家存档。

1. 新玩家、当前结构和仍需支持的旧结构均能正常初始化。旧玩家保留原有进度后，完成一条受影响的核心玩法、产生新进度、保存并重进，旧进度与新增结果都正确；仅能进场景、移动或查看旧数据不算恢复正常游玩。
2. 新增字段缺失、一个非关键字段异常与关键权益字段异常分别符合上表，不能顺带清其他数据或阻断无关初始化。
3. 读取失败或未知版本时，验证没有覆盖存档或凭默认值重复发奖；对应数据恢复可用后，相关功能能解除保护、继续游玩和保存。多人地图同时检查正常玩家不被连带卡住，不只验证“拒绝成功”。
4. 重复转换、部分保存失败和恢复重试不重复副作用、不倒写旧状态；存在异步路径时再查离开后返回及重进竞争。涉及回滚时查旧代码面对新结构的处理。

检查纯转换不能替代验证真实加载、初始化和保存的接线。没有试玩授权时运行不连接编辑器的可执行检查；缺少可执行环境或真实存储证据，就明确哪些仍待验证。静态阅读或新玩家能进图都不能证明旧玩家兼容，不得将未覆盖的升级风险写成发布就绪。

## 留给下一次开发

总览只登记存档负责模块、结构识别或版本入口、兼容范围和异常隔离边界，细节留在实现和已有测试中。迁移规则变更时收尾更新一次相关摘要；当前任务记录验证结论及未验证项，不新增兼容台账、逐轮测试日志或玩家存档副本。

依据：官方本地手册 8.28 快照中，世界版《第 11 章：数据存储与排行榜》要求处理存储失败，且注明最高分示例不是生产级存档系统；原点版《存档》分别介绍官方预设与自定义存档。本文件的兼容与隔离策略是工程约束，不是官方 API（接口）能力承诺。具体使用时仍须核对当前工程与对应手册。
