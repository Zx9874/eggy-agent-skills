# 公开版 Lua 开发硬规则

这是跨地图可复用的最小规则，不包含个人路径、地图资产编号、官方手册全文或未验证的数值结论。

## API

- 写代码前必须确认接口存在，并查完整签名、参数数量、顺序、类型、返回值、调用对象、运行端、默认值、范围和前提。
- 当前工程定义、对应版本官方手册和官方示例分别承担不同证据；三者不能互相替代。
- 资料冲突或缺少关键关系时保持未知，先研究或做最小实验，不连续改写法碰运气。

## 代码与文件

- 官方生成目录、数据映射、接口定义、工程配置和编辑器技能只读。
- 功能代码放自建模块，入口只做装配；同步到地图的 Lua 文件名使用英文、数字和连字符或下划线。
- 有准确资产编号时优先使用已确认编号；没有编号才按名称查询，并核对返回数量。
- 外部导出函数、事件名和可视化绑定名称默认冻结；任何改名、移动或签名变化先确认。

## 测试与沟通

- 没有用户要求不得启动编辑器或试玩。
- 测试以打通当前卡点为目标，先做最小可恢复试点；临时代码和日志标记 `【测试专用】`，证据足够后清理并退出测试模式。
- 正常流程用调试日志，真实异常用警告，已失败用错误；日志优先中文且避免高频刷屏。
- 报错先用大白话解释原因和影响，再按授权修复。用户未确认的功能不能写成完成。

## 注释与文档

- 每个新增或修改函数说明用途；复杂逻辑补充输入、输出、副作用、失败条件、清理时机和顺序依赖。
- 用户明确说明的修改原因才写成原因注释；完整历史放开发日志，不把聊天流水塞进代码。
- 每张地图维护一个需求文档、开发计划、资产清单、项目总览和开发日志。跨地图复用知识只有经过证据确认后才进入可靠知识库。
