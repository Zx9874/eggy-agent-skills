# 界面节点安全改名

## 边界

- 适用于原点版和世界版，但编辑器接口、节点映射和保存行为必须按当前工程版本查证。
- 不修改编辑器自动生成的技能、数据映射或官方配置；不把运行期脚本改名当成节点改名的附带动作。
- 用户未要求时不启动或重启试玩。

## 流程

1. 锁定准确地图、编辑器实例和用户指定的界面根；禁止为方便而扫描整个工程。
2. 读取节点编号、父级、顺序、类型、当前名称和可见文字，重复名称再用位置、尺寸或属性区分。
3. 在当前工程定义和官方资料中查证读取、改名、保存和回读接口；首次报错或返回语义不清时转接口研究。
4. 生成旧名到新名的冻结映射。新名按真实业务对象和控件作用命名，不能把变化中的价格、数量或状态写进名称。
5. 先改一个节点并读回；试点通过后按冻结映射逐个或分批改名。每次写入失败都保留原映射并按逆序恢复。
6. 批量完成后重新枚举目标根，核对名称唯一性、父子关系、显示文字、布局和排除项。

## 资产与代码依赖

运行代码按名称查找节点时，先静态搜索依赖并逐项更新；命中外部导出或可视化绑定时先冻结并确认。最终把当前有效节点编号、用途和保存状态写入唯一资产清单；编辑器未保存时不得声称官方映射已经刷新。
