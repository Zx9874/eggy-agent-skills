# 封面提示词模板

只读取与当前构图对应的一节。把尖括号占位内容替换成已从事实素材确认的信息，不要补写未经确认的玩法。

## 实景聚焦

```text
用途：蛋仔地图横版封面。
主请求：以图片一的真实试玩截图作满版背景，仅清除游戏界面并提升缩略图可读性；保持实际场景、对象数量和空间关系。
输入角色：图片一是事实背景；图片二是已校对标题；图片三仅供版式参考。
构图：标题“<地图名称>”醒目；只使用已确认的玩法标签“<标签>”；不为填满画面增加对象。
必须保留：<能证明核心玩法的真实场景、角色、机关、道具或界面>。
禁止：参考图中的具体人物、场景、道具、文字和玩法；地图中不存在的对象；游戏界面、评分、作者信息、二维码、水印。
输出：<用户指定比例；未指定时使用严格十六比九横版，目标分辨率 1536×864>。
```

```text
用途：蛋仔地图横版宣传封面。
主请求：借鉴风格参考的强透视、鲜艳对比、中央大标题和速度光效，但只使用当前地图事实素材。
输入角色：图片一是实际玩法场景；图片二和图片三是现有角色或玩法对象；图片四是标题素材；图片五仅作风格参考。
构图：用现有角色、机关、载具、道具或其他真实玩法对象形成动势；标题“<地图名称>”居中；副标题“<已确认玩法说明>”。

必须保留：<能证明核心动作或目标的真实内容>。
禁止：风格参考中的具体对象；地图中不存在的角色、环境、机关、道具和奖励；游戏界面、评分、二维码、水印。
```

## 玩法因果对比

适用于成长模拟、数量递增、装备进化、破坏闯关等需要在缩略图中说明“为什么会变强”的地图。

```text
用途：高点击率的蛋仔地图横版封面；缩略图中必须一眼看懂玩法因果。
核心因果：<玩家动作> → <即时反馈或成长> → <成长后的强状态与下一挑战>。
输入角色：图片一是初始状态与真实场景；图片二是成长中或后期状态；图片三是角色身份；其余图片逐张注明事实用途或仅作风格参考。所有生成输入都必须来自原始事实素材，禁止使用任何生成候选图。
构图：左侧约三分之一呈现初始或弱状态；中间用真实核心动作、破坏结果、收集反馈或不含文字的方向箭头建立因果；右侧约三分之二呈现成长后的强状态以及正在挑战的更强目标。左右环境保持为同一张地图的真实空间和材质体系。
玩法可读性：角色不能只是站立展示；必须看见他正在对什么对象做什么，且成长后的数量、尺寸、装备、速度表现或环境结果与初始状态形成强对比。
标题区：预留干净区域，生成阶段不写中文；底图通过后使用确定性本地排版添加准确标题“<标题>”和最多一个短标签“<标签>”。
光效：可以使用箭头、速度线、窄光带、火花或碎片强调方向与动作，但不得把光效变成地图中不存在的技能、武器、奖励或场景。
必须保留：<核心角色身份>、<核心动作对象>、<成长前后真实差异>、<下一挑战>。
禁止：只有角色和道具环绕、没有动作目标；前后两侧看不出成长差异；虚构玩法对象；风格参考中的具体人物和场景；游戏界面、评分、作者信息、二维码、水印；景深导致关键对象在缩略图中发糊。
输出：严格十六比九横版、全景深、锐利；最终另做五百一十二乘二百八十八缩略预览检查。
```

## 实景拼贴或多场景分区

```text
用途：蛋仔地图横版宣传封面。
主请求：只组合当前地图的真实素材，让玩家一眼看懂“<已确认核心玩法或多个玩法环节>”。
输入角色：图片一是主场景；图片二至图片四是次场景、现有角色或玩法对象；图片五是标题素材；图片六仅作风格参考。
构图：主场景占最大面积；其他事实素材作为分区或贴纸；不同地点必须保持可辨认的边界，不能伪装成同一空间；标题“<地图名称>”保持第一视觉层级。
必须保留：<各场景中证明玩法的真实内容>。
禁止：新增连接不同场景的虚构建筑、道路、机关或剧情；不得带入风格参考的具体对象。
```

## 单点修改

```text
不得把人工智能生成候选图作为生成式编辑输入。
若只修改文字、比例、位置或简单遮挡：使用确定性本地排版、裁切或布局处理，并保持真实场景、角色身份、玩法对象与整体配色不变。
精确文字：“<逐字文本>”。
若修改需要生成模型改变角色、场景、道具或动作：重新提交原始事实素材，并在新提示词中只改变“<目标变化>”；不得以上一张生成图继续重绘。
输出：严格十六比九横版；仍先保存为候选，用户明确认可后才能进入成品目录。
```
