# Lua 外部导出契约

外部调用可能完全不出现在 Lua 引用搜索中。“没有代码调用者”不能证明函数可以删除或改名。

## 先识别版本

- 原点版：`---@export` 通常是供蛋码按名称调用的 Lua 函数，必须核对蛋码侧绑定。
- 世界版：同名注解的调用方和公开包语义必须以当前世界版资料确认，不能套用原点版蛋码规则。
- `---@export_plugin` 的当前语义没有证据时只扫描、报告和停止，不按历史示例解释。

## 冻结区域

以下内容默认是绑定敏感区域：文件路径、导出注解、描述、参数注解、函数名、声明参数顺序、返回注解、紧邻注释和必要空行。用户只批准函数体修改，不代表批准其中任何契约变化。

## 修改前

删除、改名、移动、合并、拆分、重构函数或文件，修改参数名称、数量、顺序、类型或返回值前：

1. 识别当前工程版本和外部调用方。
2. 运行安装包提供的 `.eggy-agent/scripts/export-contract-audit.ps1`（导出契约扫描），目标为准确文件或目录。
3. 列出当前名称、路径、签名、调用方、拟议变化和重新绑定成本。
4. 命中导出契约时，先向用户确认具体函数和具体变化；不能用删注解、空壳、别名或改局部函数绕过。

## 新建或获准修改

- 使用当前版本官方资料确认注解格式、支持类型、运行端和加载入口。
- 原点版记录蛋码参数名称、类型、顺序、调用时机和返回接收方；世界版记录包路径以及编辑器、ECA、Lua 调用关系。
- 无必要不得进行中文和英文名称互改。准确名称必须原样传递给用户。
- 详细事件或跨端变量关系交给 `eggy-custom-event`（事件通信）或当前任务文件，不把完整契约表塞进项目总览。

## 恢复依据

- 代码文件命中导出契约时，记录现有 Git `HEAD`（当前提交）、未提交差异和允许范围即可；不得因此额外复制文件、创建 `backup/*`（备份分支）或重复提交。
- 只有同时修改 Git 无法覆盖的编辑器场景、UI（界面）或预设状态，或用户明确要求时，才建立一次目标范围快照；同一批次后续复用。

## 修改后

重新扫描并对比完整差异，确认冻结区域没有未经批准的变化。无法查看外部绑定是否更新时，状态写“待用户确认”，不能报告为完成。
