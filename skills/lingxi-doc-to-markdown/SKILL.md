# 灵犀公开文档转 Markdown

## 适用范围

本技能用于网易 PoPo 灵犀的**公开分享文本文档**：

- 输入网址形如 `https://docs.popo.netease.com/lingxi/<文档编号>`，可带查询参数和标题片段。
- 页面自身的公开访客握手必须返回可访问。
- 输出为一个 UTF-8 Markdown 文档和一个同名 `.assets` 图片目录。
- 支持重复执行；只有用户已经要求“更新、覆盖、替换”时才覆盖旧输出。

以下情况不要冒充成功：

- 分享已关闭、需要密码、仅组织内访问或当前访客没有查看权限。
- 目标是表格、幻灯片等尚未验证的非文本文档模型。
- 实时正文只取得截断历史快照，或有图片下载失败而用户没有接受远程图片回退。

## 首选执行方式

使用本技能目录内的独立脚本：

```powershell
node "<技能目录>\scripts\convert-lingxi-doc.js" --url "<灵犀分享网址>" --output "<输出文件.md>"
```

更新已有输出时，在用户明确要求更新或替换后使用：

```powershell
node "<技能目录>\scripts\convert-lingxi-doc.js" --url "<灵犀分享网址>" --output "<已有输出文件.md>" --overwrite
```

脚本只依赖 Node.js 22 或更高版本以及 Chrome/Chromium 浏览器，不依赖第三方软件包。Windows 会自动查找常见 Chrome 安装位置；其他位置用 `--chrome "<浏览器路径>"` 指定。

先运行 `--help` 可查看完整参数。不要把一次性正文网址、浏览器会话 Cookie 或访问令牌写进命令、文档、日志或任务文件。

## 标准流程

1. **确认输入与输出**
   - 校验为 `docs.popo.netease.com/lingxi/` 下的 HTTPS 分享网址。
   - 更新任务必须明确传入原输出路径，避免因标题变化生成第二份文件。
   - 覆盖前先读取已有 Markdown，确认它确实是用户指定的旧转录。

2. **执行结构化转换**
   - 脚本调用网页自身的公开访客握手。
   - 取得一次性正文入口后，让无头 Chrome 正常加载页面。
   - 通过 Chrome 开发者工具协议监听网页自己的 ShareDB 只读订阅结果。
   - 根据对象结构识别完整正文，不依赖固定文档大小或固定帧长度。
   - 不发送写操作，不尝试修改分享设置或绕过权限。

3. **本地化图片**
   - 递归收集块级和行内图片，按首次出现顺序编号。
   - 仅向网易正文域发送临时访客 Cookie；重定向到对象存储后不继续转发 Cookie。
   - 按文件签名识别 PNG、JPEG、WebP、GIF、AVIF 或 SVG，拒绝把错误页伪装成图片。
   - 默认任一图片失败就终止替换，保留旧输出不变。

4. **安全替换**
   - 新文档与图片先写入同目录临时路径。
   - 全部转换和校验成功后再替换目标 Markdown 与同名 `.assets` 目录。
   - 替换失败时回滚旧文件；不得留下“正文已更新但图片仍是旧版”的半成品。

5. **验收**
   - 读取脚本最终输出的 JSON 报告。
   - 确认 `imagesFailed` 为空、`uniqueImages` 等于本地图片文件数、`missingLocalImages=0`、`invalidLocalImages=0`；同一图片在正文中重复出现时，图片节点数可以大于唯一图片数。
   - 确认正文节点数、表格数、列表数等统计合理，且输出 Markdown 不为空。
   - 抽查第一张和最后一张图片；必要时打开 Markdown 预览确认相对路径显示正常。

## 转换规则

- 文档标题写为一级标题，并保留原始分享网址注释。
- 原文标题使用对应 Markdown 层级，并用原节点编号生成 HTML 锚点。
- 粗体优先使用 Markdown；下划线、颜色、删除线等 Markdown 无法稳定表达的样式使用最小 HTML 标签。
- 有序列表与无序列表按原始 `listType` 精确区分，禁止用子串判断导致 `unordered` 被识别成 `ordered`。
- 表格转换为 Markdown 表格；跨行或跨列合并单元格用空占位列维持后续内容对齐。
- 图片使用 `./<文档名>.assets/<图片文件>` 相对路径；不保留需要登录才能打开的网易远程地址。
- 未识别的普通容器递归保留其可见文字；无法可靠表达的结构必须在报告中警告，不能静默丢弃。

## 失败与回退

按以下顺序处理，不自动跳到 OCR：

1. 检查公开访客握手和分享权限。
2. 检查一次性入口、浏览器安装和实时正文订阅。
3. 若网页当前实现变化，定向检查其公开前端脚本和网络请求，更新本技能脚本。
4. 官方导出只有在当前会话本来就有导出权限时才可使用；访客返回无权限时不能绕过。
5. 历史快照只有在明确未截断且结构完整时才能作为正文来源。
6. OCR 只作为用户知情同意后的最后手段，输出必须标明可能存在识别误差。

`--allow-remote-images` 会允许失败图片回退到远程地址，可能在离线预览或会话失效后无法显示。只有用户明确接受这一差异时才可使用。

## 安全边界

- 只处理公开分享允许读取的文档。
- 不枚举文档编号，不猜密码，不修改权限，不发送 ShareDB 写操作。
- 访客 Cookie 和一次性代码只保存在进程内存及临时浏览器配置中，清理后不得复用。
- 不把 Cookie 转发给网易正文域以外的重定向主机。
- 当前接口属于网易网页私有实现，不是稳定开放接口；网页构建变化后需要重新做最小验证。

## 文件说明

- `scripts/convert-lingxi-doc.js`：无第三方依赖的通用命令行转换器。
- 维护注意事项以本技能正文和脚本 `--help` 输出为准；不要把访问令牌、Cookie 或一次性网址写入项目文件。
