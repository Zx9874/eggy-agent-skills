# 蛋仔地图策划共用入口

本文件只保存原点版与世界版真正通用的策划入口和完整性检查，不保存两版不同的世界运行规则。它不是固定问卷；先处理父级决定，每轮从当前决策前沿选择两个互不依赖的问题。

## 导航

- “选择第一条路”：判断从零、参考玩法、组件想法或已有策划中的哪一点开始。
- “版本分流”：识别或确认原点版与世界版，并只加载一个版本分支。
- “共用父级决定”：确认玩家承诺和核心循环。
- “共用系统检查”：检查功能、成长、失败恢复、教学和反馈。
- “完整性门禁”：正式输出前检查共同部分和版本专属部分。

## 一、选择第一条路

- 只有题材或场景：从玩家在这个世界中扮演谁、最常做什么开始。
- 只有参考作品：确认最想保留哪一种体验，不照搬全部系统。
- 只有组件或官方系统：确认它为玩家解决什么问题，不能为了使用组件反推一整张地图。
- 完全空白：推荐一个范围可控、核心循环清楚、首次试玩就能判断好不好玩的体验方向。
- 已有策划：先找对核心循环、人数、开始结束或奖励去向有影响的矛盾与空白。

同一轮选择两个不互相依赖的父问题。例如“玩家主要体验”可以和“版本是否已经固定”同轮询问；“推荐哪个版本”必须等主要体验明确后再问。

## 二、版本分流

1. 已有工程：按路径和工程配置识别版本，不询问用户已经能查到的事实。
2. 没有工程但用户已明确版本：记录决定，直接进入对应分支。
3. 没有工程且版本未定：第一轮询问核心体验，以及版本是否已经固定或希望代理后续推荐。
4. 核心体验明确后，根据当前本地官方定位资料给出版本建议和取舍，由用户决定。
5. 用户选择与典型定位不一致时，只说明可能的体验差异并让用户确认，不替用户改版。

版本确认后只加载一份：

- 原点版：[原点版策划分支](origin-planning.md)
- 世界版：[世界版策划分支](world-planning.md)

禁止把原点版的“所有参与者重演同一场游戏”假设写进世界版，也禁止把世界版的“持续统一世界、随进随出”假设写进原点版。

## 三、共用父级决定

### 1. 玩家承诺

- 玩家扮演什么角色，进入地图是为了获得哪种主要体验。
- 一句话描述应包含玩家行动和吸引力，不能只有世界观或功能清单。
- 目标玩家是谁，面向新手、熟练玩家、朋友组队还是陌生人同场。
- 预期单次体验多长，只在确实影响节奏时询问。

### 2. 核心循环

- 玩家第一次进入后十秒内看到什么、第一步做什么。
- 玩家反复执行的主要行动是什么，行动后立即得到什么反馈。
- 奖励或进度怎样让玩家自然进入下一轮行动。
- 循环如何变化，避免只有重复而没有新目标。
- 玩家为什么愿意再玩一次或第二天回来。

只有核心循环能用具体玩家行为完整讲通，才展开附属系统。

## 四、共用系统检查

### 3. 单个玩法系统

每个真实存在的功能依次确认：

- 玩家目的和触发前提。
- 玩家进行的操作。
- 立即看到、听到或感受到的反馈。
- 成功后改变的状态和下一步。
- 失败、资源不足、重复操作或中途离开时的结果。
- 一个最短可试玩验收场景。

不要按代码模块提问，也不要为不存在的系统创建空分支。状态归属、玩家加入离开和多人冲突按当前版本分支询问。

### 4. 成长、经济与内容

- 玩家获得什么，消耗到哪里，为什么值得积累。
- 解锁、价格、库存、等级或生产进度之间的关系。
- 进度是否保存，哪些内容重置，哪些长期保留。
- 资源耗尽、达到上限、重复领取和刷取行为怎样处理。
- 内容按什么顺序开放，难度和奖励怎样变化。
- 首个可试玩版本需要哪些内容，哪些明确留到以后。

### 5. 失败、恢复与结束

- 哪些情况算失败，失败损失什么，玩家从哪里继续。
- 玩家卡住、走错、资源不足或错过关键步骤时如何恢复。
- 胜利、结算、阶段完成或长期目标的可见条件。
- 结束后再次游玩怎样处理；具体回合或持续世界生命周期由版本分支补充。

### 6. 教学与反馈

- 新玩家按什么顺序理解核心玩法，第一项引导何时消失。
- 界面只显示玩家此刻需要知道的信息，长文本是否能读完。
- 操作成功、失败、资源变化、解锁和危险是否有不同反馈。
- 重要反馈需要文字、声音、动画或场景变化中的哪些组合。
- 不认识文字、没开声音或多人同时收到提示时是否仍能理解。

## 五、范围与现实检查

- 当前正式策划包含什么，明确不包含什么。
- 哪些属于首个可试玩版本，哪些是后续想法。
- 某个设计是否依赖尚未确认的编辑器能力、资产或表现参数。
- 是否存在不能服务核心循环、只是为了显得功能多的附属系统。
- 是否有两个规则使用同一名词却含义不同，或同一概念使用多种名字。

平台能力是事实问题，代理查对应版本资料；是否接受玩法取舍是用户决定。

## 六、共用完整性门禁

正式策划前逐项判断“已确认、不适用、待确认”：

1. 玩家角色、主要目标、目标玩家和核心体验。
2. 原点版或世界版已经确认，且只使用对应版本分支。
3. 进入、核心循环、推进和结束或长期目标。
4. 每个玩法系统的前提、操作、反馈、成功、失败和重复操作。
5. 经济、成长、保存和内容节奏中实际存在的部分。
6. 失败恢复、卡住恢复、教学和关键反馈。
7. 首个可试玩范围、明确不做的内容和可试玩验收。
8. 当前版本专属完整性门禁全部通过。
9. 所有会改变核心体验的未知项都有用户决定或明确保留为待确认。

存在会影响主流程的“待确认”时，从已解锁前沿继续选择两个问题。只有用户要求暂停或先出草案时，才带着待确认项收束。
