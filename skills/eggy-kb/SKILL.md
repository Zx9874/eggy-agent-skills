# 蛋仔可靠知识

可靠知识库保存以后确实值得复用的结论，不保存开发流水账。旧知识库只能提供搜索词，不能直接升级为可靠结论。

## 何时记录

同时满足以下条件才写可靠知识库：

1. 结论不只服务当前一张地图。
2. 原点版或世界版、运行位置、对象和适用范围明确。
3. 有当前工程定义、对应官方资料、官方示例、可重复实际观察或开发人员原话中的有效证据。
4. 结论能避免以后重新研究，或者能阻止代价较高的错误复发。

普通改名、一次性业务逻辑、实例编号、测试工具手误、只出现一次且原因明显的失败、没有证据的猜测均不记录。单地图观察但以后可能有价值时，只在当前任务载体留一条紧凑待复核摘要。

## 最小条目

每条只保留能让下一位代理安全复用的内容：

- 结论。
- 版本、运行位置、对象和适用范围。
- 来源与证据位置；开发人员答复尽量保留提问原文和答复原文。
- 最小复现或核对方法。
- 验证日期、当前状态和仍未证明的边界。
- 旧结论失效时的替代条目。

不要求保存每轮实验、完整原始日志、大段代码或重复的接口定义。证据之间冲突时标为“冲突待处理”，不得自行选边。

## 状态

- **已确认**：版本、对象、范围和证据明确；当前工程签名与环境一致时可以复用结论，但新增或修改接口仍要做当前工程查证。
- **已观察**：只在指定地图或环境出现；换地图先做小范围复测。
- **待复核**：版本、签名、官方说明或环境变化；复核前不能用于正式实现。
- **待验证、范围待补充、冲突待处理、已失效**：不能作为正式代码依据。

世界版工具或接口版本变化时，相关运行观察优先转为待复核。

## 使用与更新

使用前只检查当前任务命中的条目：版本、运行端、对象、完整签名、官方说明和适用边界。全部一致才沿用；任一关键项变化就重新研究。

- 一个研究或开发批次只在收尾时更新一次对应主题文件。
- 同一结论补充复核证据时更新原条目，不创建重复条目。
- 行为实质变化时保留旧条目并标为失效，新建替代条目并互相引用。
- 一次只修改对应主题和必要索引，不批量清洗全库。
- 普通新事实不立即修改技能；只有稳定、高频、错误代价高且经过复核的流程经验才升级技能。

代理写错接口后，先在当前任务内完成原因分析和最小验证；只有最终确认的参数关系、边界或错误模式达到上述门槛时才沉淀。不要把“这次写错了”本身写成知识。

向用户简洁说明记录位置、结论、证据等级、适用范围和什么变化会触发重新验证。
