# 蛋仔运行日志与报错

本技能只处理运行日志和报错。开发任务与用户原话由当前任务载体管理，代码历史由 Git 管理，不把三者混进日志文件。

## 排查本次试玩

1. 确认当前工程和用户最近一次复现步骤。
2. 优先用试玩开始前记录的字节位置或时间读取新增日志；没有边界时只看最近区间，并把旧错误标为历史待确认。
3. 相同错误合并为首条业务位置、重复次数和最后时间；一条调用链只保留定位原因必需的部分。
4. 区分日志直接证明、结合代码确认和仍是推测，不把相邻时间当成因果。
5. 先用用户能理解的中文说明现象、已确认原因、影响和保留原效果的修复方向，再按根规则的授权模式继续或停止。

不把整段原始日志粘进任务文件、任务索引或回复。只有错误尚未解决且需要跨会话继续时，才在当前任务载体留下错误摘要、证据区间和下一步。

## 功能试玩前的可判定观察门禁

用户已经明确授权通过试玩验证代码行为时，在启动前检查本轮观察目标：

1. 至少能从日志判断是否进入目标流程、关键条件或输入是什么、最终成功或失败结果是什么。
2. 现有日志完整覆盖这三个判定点时直接复用；缺失时在现有正式调用点加入最少量的 `【测试专用】` 调试日志，不默认新建测试文件。
3. 多人行为同时记录必要的操作者、状态归属或接收者，不能只证明某个未识别玩家触发过。
4. 高频路径只记状态变化、首次异常或首尾摘要，禁止逐帧和无条件循环打印。
5. 试玩前记录日志边界，试玩后只分析本轮新增区间；证据足以决定下一步，或者已经阻塞、等待用户操作时退出本轮观察，除等待用户继续执行当前已授权试玩外，清理临时测试打印。

纯启动、停止、编辑器状态检查或只读取已有报错时，不为了流程仪式新增打印。

## 新增或修改运行日志

- `GlobalAPI.debug()`：正常流程、状态变化、测试观察和开发诊断。
- `GlobalAPI.warning()`：真实异常，但功能仍能继续且需要开发者注意。
- `GlobalAPI.error()`：关键流程确定无法继续或关键数据无效。

项目使用 `LuaAPI.log(内容, 等级)` 时，沿用当前项目已经查证的等级约定；语义未确认的数字等级不得新用。

日志应当：

- 优先中文，包含功能、动作、结果和必要编号。
- 只在状态变化、一次性结果或异常首次发生时输出。
- 高频回调使用去重、限频或首尾摘要，禁止逐帧刷屏。
- 正常缺货、等待、初始化成功等正常状态不得为了醒目使用警告或错误。
- 不输出凭据、个人信息或无关的完整数据结构。
- 只要是新增的测试日志就带 `【测试专用】`。同一运行应一次布置当前开发决策所需且互不干扰的关联观察；证据充分后立即清理。等待期间只保留已有必要观察点，不继续追加无关日志。

无需在任务载体预先建立日志清单。只有日志等级或高频行为本身是本次任务核心、需要跨会话交接时，才留下短说明。

## 审查

本次确实新增、修改或删除日志时，运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<本技能目录>\scripts\log-audit.ps1" `
  -ProjectPath "<当前工程绝对路径>" `
  -ChangedFile "<修改文件1>","<修改文件2>"
```

脚本只列出调用和字面等级，代理仍须结合触发条件判断。没有改动日志且本次没有报错时，不为流程完整感加载本技能或运行审查脚本。

向用户只说明本轮错误组、已确认原因、影响、日志等级变化、当前修复与验证状态；不要堆原始日志、Lua 代码或接口细节。
