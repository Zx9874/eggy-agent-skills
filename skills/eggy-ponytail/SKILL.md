# 蛋仔地图与工具极简开发

本技能只回答“当前交付物能否用更少、更直接的实现完成”。

## 任务域

- **蛋仔辅助工具**：默认使用。读取工具自身仓库、入口、调用方、测试和配置，不询问地图，不加载地图 Lua 规则或地图项目文档。
- **地图运行代码**：普通开发由 `eggy-lua-coding` 内置原则处理；只有用户明确提出精简类请求时才使用本技能，并复用主开发流程已经确认的事实。
- **普通非蛋仔项目**：不使用本地技能；按该项目自身规则处理。
- **混合任务**：按修改文件分别应用，工具源码和地图运行代码不能共享彼此的流程门禁。

## 边界

- 工具开发直接使用目标仓库事实；地图精简使用地图主开发技能已经确认的事实。不得为了加载本技能再执行另一套启动、检查、文档或收尾流程。
- 用户明确要求的效果和当前真实消费者不能为了代码更短被删除、降级或改写。
- 不为“极简模式”新建测试框架、技术债账本、文档或额外汇报；按目标仓库现有验证方式留下与风险相称的最小检查。
- 蛋仔接口语义不明确时加载 `eggy-api-research` 的对应模式，不因此切换任务域。
- 蛋仔相关任务只使用本地技能，不加载全局 `ponytail*` 或上游原文。

## 实现精简

理解用户效果和真实执行链后，依次选择第一个完整可用的方案：

1. 删除代理自己设想、当前没有消费者的未来能力。
2. 复用工程已有且职责正确的实现或状态所有者。
3. 优先使用目标运行环境已支持的标准能力、原生能力和现有依赖。
4. 直接实现当前需求，不增加无消费者的配置、包装、依赖或扩展点。
5. 只有抽象能消除当前真实重复或降低现有复杂度时才增加抽象。

“最小”按完整用户效果、清晰状态归属和最低误改风险判断，不按行数或文件数机械判断。修复先找共同根因；补丁会留下同类错误时，修共同路径才是更小的长期改动。

## 按需操作

用户要求过度设计审查、全项目审计、技术债清点、收益说明或帮助时，只读取 [对应操作](references/operations.md) 中当前任务域和请求命中的一节。
