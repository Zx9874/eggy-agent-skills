# 蛋仔预设导入导出流程

## 强制边界

- 预设操作会改变编辑器资产，先确认当前工程、版本、源预设、目标用途和允许写入的目录。
- 使用用户目录 `.eggitor\cli\editor-cli.exe` 和动态连接，禁止工程旧工具路径与固定端口。
- 导入、导出、查找和验证所需的每个编辑器接口都执行编码技能的 API 查证门禁。本技能不保存固定接口签名。
- `Data/Prefab.lua` 和其他官方映射文件只读，禁止通过预设流程手工修改。
- 禁止使用保护性调用把接口错误、路径错误或导入失败变成表面成功。
- 禁止批量复制脚本。多个预设按清单逐个导出、核对、导入和验证。
- 普通的单个预设查询、导出或导入不自动建立文件备份；只有目标会被覆盖、跨工程迁移需要保留原状态，或用户明确要求时，才为本批目标建立一份回退副本，并在同一批次复用。

## 动工前确认

在当前任务中确认：

1. 源工程、目标工程和各自版本。
2. 源预设名称与已确认编号；没有编号时记录查找方案。
3. 导出文件的绝对路径、用途和是否允许覆盖。
4. 目标预设名称、冲突处理方式和用户可试玩验收标准。
5. 准备调用的接口已经通过当前工程和官方资料查证。
6. 操作失败时保留原预设和文件的回退方式。

路径、名称、编号或覆盖策略有歧义时先询问用户，不自行选择。只有操作跨会话、多预设批次或存在未解决风险时，才把上述范围紧凑写入当前任务载体。

## 单个预设操作

1. 通过编辑器命令行技能确认当前连接和编辑模式。
2. 用已查证接口读取或确认源预设，不凭名字相似猜编号。
3. 导出到计划中批准的文件路径；文件已经存在时停止并询问是否覆盖。
4. 检查命令结果、增量日志、文件是否存在及文件大小，记录导出证据。
5. 需要迁移时切换到用户明确指定的目标工程，重新核对工程与版本。
6. 用已查证接口导入单个文件，随后查询新预设并确认名称与编号。
7. 将新预设编号、名称、来源、用途、验证状态和重要参数写入目标项目资产清单。
8. 当前预设验证通过后，才处理清单中的下一个预设。

## 变体与属性修改

- 导入后修改缩放、受力或其他属性属于独立编辑器修改任务，相关接口另行查证。
- 用户明确说明修改原因时写入相关代码注释或必要计划摘要，代理推测不写成原因。
- 每次只改一个预设的一组明确属性，并读回或通过编辑器画面验证。
- 不通过编辑映射文件制造预设变体。

## 失败处理

- 命令失败、文件未生成、导入后查不到预设或编号冲突时立即停止。
- 保存本轮增量日志和已经成功完成的步骤，不继续批量处理后续预设。
- 先用中文说明失败发生在哪一步、已确认原因、对现有预设是否有影响和回退方式；用户确认后再继续。

## 回执

向用户逐项列出成功处理的预设名称与编号、导出文件、目标工程、资产清单位置、失败或待确认项，以及还需在编辑器中手动检查的最短步骤。没有验证的预设不能写成导入成功。
