# 蛋仔地图试玩

自动试玩只能证明地图能否启动、指定观察范围是否出现新增报错，以及少量可自动触发的状态。它不能替代用户对操作、视觉、手感和多人效果的确认。

## 单轮流程

1. 确认工程、地图版本、本轮要打通的开发卡点，以及证据将决定的下一步动作。
2. 本轮要验证代码行为时，读取编码技能和日志技能，确认现有日志能判断是否进入、关键条件和最终结果；不足时先按代码门禁在现有正式调用点加入最小 `【测试专用】` 打印并完成静态检查。
3. 读取编辑器命令行技能，使用用户目录工具和动态连接。
4. 记录 `log.txt` 当前字节位置；不清空旧日志。
5. 检查编辑器状态并开始试玩，等待状态确认，不只等待固定秒数。
6. 只执行本轮决策所需的最短玩家流程，并在这一次流程中取得所有互不干扰的关联观察。需要用户点击、移动或配置时，直接给出合并后的最短步骤。
7. 停止试玩并确认回到编辑状态，只读取本轮新增日志。
8. 归并重复错误，结合测试打印报告实际证据和当前状态。
9. 证据足以决定下一步，或者已经无法安全继续、阻塞或等待用户操作时，结束本轮试玩测试并返回正式开发、接口研究、等待用户或收尾，不把“测试中”状态带入后续代码工作。

正常的启动、停止、状态和日志工具命令不需要每轮建立接口证据卡。只有通过命令行调用新的编辑器或运行时接口时，才按编码技能查证该接口。

纯启动、停止、编辑器状态检查或只读取已有报错时，不为了试玩仪式新增测试代码。验证新增、修改或修复的代码行为时必须先具备可判定打印；已有日志完整覆盖时复用，缺失时只加入当前观察问题所需的最小 `【测试专用】` 调试日志。不得为此默认创建独立测试文件。

## 结果与报错

- 没有新增报错：只报告“本轮观察未发现新增报错”。
- 出现报错：先用中文说明现象、已确认原因和影响，再按根规则授权模式继续或停止。
- 原因不明、接口无效果或准备换参数时：停止扩大，转入 `eggy-api-research`。
- 不自动重启并连续跑多轮；只有新证据对应一个明确修复或用户明确要求继续控制试玩时才开始下一轮。
- 用户未确认时，功能状态保持“待试玩”或“待用户确认”。

结果已经支持下一步开发动作时结束当前批次：通过或不再需要复测时清理临时观察内容；失败后回到正式修复或接口研究；需要用户操作时保留现有必要打印并冻结代码，不得趁等待继续添加测试函数。部分验证或无法区分仍卡住开发时，只提出能直接补齐决策证据的最短后续观察；下一批次必须说明正式修复或新证据为何使上一轮结论不足。

普通试玩不写长期测试记录。只有结果改变任务状态、留下跨会话阻塞或用户给出反馈时，才更新当前任务载体。

向用户简洁说明本轮范围、是否进入和退出试玩、新增错误数量、当前结论和最短后续操作。
