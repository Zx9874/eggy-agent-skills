# 蛋仔地图开发任务管理

## 三层记录

1. **任务索引**：每张地图维护一个 `docs/开发计划.md`，只保存活跃任务、收件箱、依赖、文件指针和最近确认结果。新会话先读它，不从头翻历史任务。
2. **任务文件**：仅在任务确实需要独立上下文时，创建 `docs/开发任务/DEV-YYYYMMDD-NN-简短名称.md`。一个文件只负责一个可试玩结果或一个明确研究问题。
3. **技术历史**：具体代码差异、修改文件和过程由 Git 保存，不复制成开发流水。

需求玩法、资产、项目架构和跨地图可靠知识仍分别写入 `docs/需求文档.md`、`docs/资产清单.md`、`README.md` 和可靠知识库。任务索引与任务文件只保存仍会影响执行或验收的信息。

创建、拆分、迁移或收束任务时，读取 [references/task-files.md](references/task-files.md)；普通状态更新不必重复读取模板。

## 项目总览

每张地图只维护一个工程根 `README.md`，作为新会话的一页项目总览。新建总览、发现总览缺失，或玩法主循环、主要系统、入口、模块边界、状态所有权、跨端数据流、存档边界、外部调用方向、调用方类别、归属系统或主要系统整体实现状态发生总览级变化时，读取 [references/project-overview.md](references/project-overview.md)。

- 总览回答“玩家怎么玩”和“当前代码怎样把玩法串起来”，不保存任务流水和完整技术细节。
- 玩法摘要只来自当前 `docs/需求文档.md`，当前实现架构只来自工程代码、配置和已确认外部绑定；两者不得互相推断。
- 普通参数调整、局部修复、函数内部重写、日志变化和资产编号变化不更新总览。
- 总览缺失不阻断只读诊断或很小的局部修复；首次正常开发批次补建。已有 `docs/README.md` 只能作为旧文档索引线索，不能替代根项目总览。
- 创建或更新总览后只读回本次改动的相关段落，确认玩法来源、代码证据、未来计划边界和文档入口；不运行独立格式审计，不为满足固定标题、图表或篇幅而改写内容。

## 总览优先路由

- **已有总览**：先读根 `README.md`，再只读 `docs/开发计划.md` 的活跃任务表；用户指定任务后，只加载该任务文件及其明确链接。没有命中当前任务的需求细节、资产编号、接口和历史报告都不加载。
- **总览缺失**：正常开发或文档整理批次先补建根 `README.md`。只读取项目 `AGENTS.md` 的项目事实、需求文档的标题和相关章节摘要、开发计划的活跃任务、入口文件和自定义一级目录；不通读全部需求、资产表、接口定义或历史记录。
- **证据不足**：在总览中写“未知”或链接到待查任务，不用猜测填满；事实冲突时先记录冲突，不把两份资料拼成新结论。
- **补建完成后**：同一批次只做一次语义读回，然后进入用户指定任务；总览不是新的任务正文，也不复制接口查证和资产明细。

## 选择任务载体

同时满足以下条件时，只在任务索引内维护一张简短任务卡，不新建文件：

- 预计当前会话可以达到待试玩。
- 只有一个清楚的玩家可见结果。
- 没有独立阻塞、外部模型交接或高风险契约。
- 用户原话、代理理解、验收和下一步可以紧凑写清。

出现任一情况时创建独立任务文件：

- 预计跨会话继续，或另一个会话、代理、外部模型会接手。
- 包含多个能够独立试玩的纵向任务，且存在先后依赖。
- 接口或编辑器行为需要跨会话研究，或结论会决定多个正式调用点。
- 涉及导出契约、存档、多人共享状态、大范围迁移或其他高风险改动。
- 用户原话和验收细节放进索引会使索引难以扫描。

不要按文件、模块、接口或开发步骤横向拆任务。拆出的每个任务应交付一个可单独观察或试玩的结果，并明确“阻塞于哪些任务”。

## 执行循环

1. 读取项目规则和任务索引；用户指定任务编号或任务文件时只加载该任务及它明确链接的资料。
2. 新需求先保存“用户原话”，再写“代理理解”和“可试玩验收”。用户只是想到以后要做的内容时，先进入收件箱，不擅自扩写技术方案。
3. 为持久任务分配稳定编号。索引保存摘要和指针，详细内容只写在任务文件，禁止两处复制同一段正文。
4. 开发只推进当前任务。途中发现的独立问题进入收件箱，不顺手扩大范围。
5. 只在需求含义、范围、依赖、阻塞、负责人、验收结果或下一步发生变化时更新；搜索、保存、每个函数、每轮测试和普通手误不更新。
6. 达到待试玩时记录最高验证等级、最短试玩步骤、遗留问题和提交引用；状态保持“待试玩”或“待用户确认”。
7. 只有用户明确确认后才能写“用户确认完成”。随后把最终玩法、资产、架构和可靠知识归位；只有项目总览触发项发生变化时才更新根 `README.md`，再收束任务文件和索引。

## 多会话一致性

- 地图可以同时存在多个进行中任务，但每个任务必须有唯一编号、明确负责范围和一个权威任务载体。
- 多个任务共享的事实不得分别抄进任务文件；先更新需求文档、资产清单、项目说明或可靠知识库，再由任务文件链接。
- 同一任务不得由两个会话同时修改。需要转交时覆盖更新“最近正确交接”，写明当前状态、已排除路线、剩余未知和下一动作。
- 用户说“继续”且索引中只有一个活跃任务时直接继续；存在多个候选且用户没有指定时，先列出候选让用户选择。

向用户只报告本次更新了哪个任务编号、使用了索引卡还是独立任务文件、当前状态和下一步，不粘贴整份文档。
